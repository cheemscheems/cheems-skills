# 输出模板

## 零、论文介绍（交付物开头固定）

交付物开头先给一段“论文介绍”，让不熟悉该领域的读者也能读懂这篇论文。

| 项目 | 要求 |
|---|---|
| **领域** | 研究方向与要解决的问题，一句话，用初学者能懂的话 |
| **方法** | 核心做法，一句话 |
| **性能** | 关键结果的数字：在哪个数据集／基准上，用什么指标，达到多少 |
| **比较对象** | 与哪些方法比较（名称 + 年份）；是否包含该领域较新的方法 |
| **创新点** | 作者主张的贡献，1–3 条 |

要求：用简明通用语言；英文术语首次出现给中文解释；这一节只做客观介绍，不展开批评（批评放在后面的主要问题）。

## 一、口径声明（报告开头固定）

只列适用的：± 口径（SD / SE / CI）｜micro vs macro｜strict vs relaxed｜百分点 vs 相对提升｜单次运行 vs 多种子平均｜域内对比 vs 零样本迁移｜实体指标 vs 关系指标。
**凡引用 mean ± X，先写明 X 是什么；比较时同时给出 SD 与方差（SD²）。**

## 二、主要问题：深度证据块（默认，关键内容加粗）

### M<n>. 标题（一句话问题）

- **位置**：PDF p.X（印刷 p.Y），章节／表号／图号
- **原文（EN）**："..."
- **中文翻译**：...
- **事实核验**：数据、复算公式与结果、对照来源
- **为什么是问题**：逐步推理；必要时给 A/B/C 场景分析
- **影响**：是否颠覆结论、影响哪张表／哪个主张
- **必要修复**：1) ... 2) ...
- **改好后如何判断**：...

- [m-1] 问题（位置：PDF p.X / 表 Y）→ 最小修改

## 五、审稿句式（中英对照，可直接粘贴）

英文模板与中文模板，逐条对应上文问题编号。

## 六、单位与格式复核清单（第二轮使用）

- **非必要不新增**单位或格式；已有单位必须与原文一致且正确。
- 检查项：%、pp、±、SD/方差、小数点位数、千分位、单位符号、大小写、连字符、正斜体。
- 不做无依据换算；凡换算必写算式与结果。

## 七、语言与可读性（硬性）

**① 中英成对**：交付文件中每一条英文语句都必须紧跟对应的中文翻译（原文 + 译文成对出现）。专有名词、方法名、指标名、数据集名保留英文；表格单元格内的英文引用同样附译文。

**② 简明易懂（面向初学者）**
- 用通用词汇，**不自造术语或黑话**；skill 内部的流程名与编号（Pass、A1–A10、“三分法”“证据块”等）**不写进交付物**。
- 缩写首次出现给全称；英文术语首次出现给中文解释。
- 一句一个意思，句子要短；先给结论，再给依据。
- 不堆砌形容词和套话（如“非常重要”“值得注意的是”“综上所述”“众所周知”）。
- 并列信息用表格，不用长段落罗列。
- 同一意思只说一次，不用同义词反复强调。

**正例 / 反例**

| 反例（堆砌 + 自造黑话） | 正例（简明） |
|---|---|
| 本稿在 provenance 层面存在负外部性，作者对 baseline 的 attribution 呈现显著性不足。 | 这些对比数字的来源没有交代清楚：哪些是作者自己跑的、哪些是引用别人的，读者看不出来。 |
| 该模块的解耦性设计对 ordered entity pair 的 role-specific 表征具有实质性增益。 | 把“头实体”和“尾实体”分开处理后，模型更能分清谁作用于谁，所以关系方向的判断更准。 |

**③ 目标**：让非本领域的读者也能读懂。如果一句话需要读两遍，就改写。

## 八、子代理产出的接入规则

- 子代理**不设产出上限**：报告全部发现并按严重性排序，确实没有则写“无”。
- 每条必须含 **原文具体位置**（PDF 页码 + 印刷页 + 章节／段落／表号／图号 + 定位短句）与**中英对照引用**。
- 进入报告前必须通过“anchor／quote_en 在指定位置逐字命中”的机械校验。
- 重复项合并并标注“多视角一致（A1+A2）”；分歧标“视角分歧”并由主代理裁决。
