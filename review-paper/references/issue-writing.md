# 单条意见写法、深度证据块与二轮复核

> 何时读我：正在写具体某一条意见、需要证据块格式，或执行二轮复核时。

## 单条意见写法

- 使用编号和小标题，先写可核验事实，再写判断；正式英文意见保持客观、坚定、建设性，中文讨论可解释推理。
- **用简明语言**：避免自造术语与黑话；缩写与英文术语首次出现时给全称／中文解释；句子短、先结论后依据。
- 不要用内部流程名（Pass、视角编号、“三分法”等）向作者说话——它们只是内部组织工具。
- 每条应尽量回答：**在哪里、写了什么、为什么确定有问题、影响什么、作者必须做什么**。修复要求应与问题一一对应，优先要求最小充分修复。
- 涉及前后不一致时，同时给出冲突两端的位置和原文；涉及首次定义时，给出实际首次出现位置及定义位置；涉及符号复用时，给出每种含义所在的公式或段落。无法提供具体位置时，继续核验，不把概括性怀疑写入 Minor Issues。
- 允许使用“Please verify…”“The manuscript states…, whereas…”“This inconsistency affects…”等明确表达；不要用攻击性、讽刺或无法证明的指控。
- 审稿意见和作者回复应逐条对应。回复可采用“Response → Changes made → Location”，具体列出修改位置、数字、公式、图表或补充实验；只在实际完成后声称“we have revised”。
- 长度以信息密度为准；历史风格偏向清楚、可执行、不为显得专业而拉长。对摘要背景等问题曾明确要求 shorter is better。

## 主要问题：深度证据块（默认格式）

每条 Major 默认按下列结构展开（模板见 [output-templates.md](output-templates.md)）：

> 一句话问题 → **位置**（PDF 页 + 印刷页 + 章节／表号／图号） → **原文（EN）** → **中文翻译** → **事实核验**（复算／对照来源） → **为什么是问题**（逐步推理，必要时给 A/B/C 场景分析） → **影响**（是否颠覆结论） → **必要修复** → **改好后如何判断**

- **关键内容加粗**；引用保留英文原文，并附中文翻译。
- 次要问题保持一行一条（问题 + 位置 + 最小修改），不展开，避免稀释重点。
- 报告固定收尾：① 核验覆盖率表；② 未覆盖项与残余风险；③ 可直接使用的审稿句式（中英对照）。

## 二轮复核机制（内部执行）

1. **第一轮**：核验取证，写出审稿草稿。
2. **第二轮**：只针对草稿复核——数字复算、单位与格式、位置与页码、术语一致性、引用与原文比对、是否有未声明的抽样；对子代理的视觉结论**二次检查**。
3. 定稿只呈现最终结论与更正后的内容；**复核与自查过程不向用户展示**。
